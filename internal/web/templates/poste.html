Règles de la console

  • profile.bucket, endpoint et region : ceux de ce bucket.
  • profile.aws_credentials: credential:<nom> : la clé du poste, créée par la console avec le paquet.
  • Aucun secret en clair : URL de ping et jetons en credential:<nom>, valeurs saisies à la création du paquet (jamais conservées par la console).
  • profile.aws_cli vide (ou C:/Program Files/Amazon/AWSCLIV2/aws.exe, /usr/local/bin/aws sous Linux) : la CLI AWS est installée par kura-agent install si elle manque.
  • Sources : chemins complets du système du poste (D:/Donnees, ${PROFILE:alice}/Documents ; /home/alice/Documents sous Linux).
  • Sous Linux : ni pre_tasks, ni post_tasks, ni tray (pas d'icône) ; la CLI AWS en snap n'est pas utilisable par le service.
  • Le texte est conservé tel que saisi, commentaires compris : n'y écrire aucun secret, même en commentaire. Un seul document YAML (rien après ---).
  • Préparations (prepare, tools, encryption) : outils et sources en chemins complets du système du poste ; sous Windows, 7-Zip seulement pour zip ; SQL Server sous Windows seulement ; mot de passe d'une base en credential:<nom>, saisi à la création du paquet ; un job envoie ${STAGING:<id>}, jamais le clair d'une préparation chiffrée.
  • Clés publiques seulement : une clé privée gpg ou une identité age (AGE-SECRET-KEY-…) est refusée.
  • Les sources, les comptes (${PROFILE:…}, tray), les outils (présence, version, droits) et les clés gpg sont vérifiés sur le poste, par kura-agent install et validate.
